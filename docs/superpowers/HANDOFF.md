## Architecture facts later work depends on
- Core (`packages/core`) is pure TS, verified byte-identical against upstream NHSE.Core through the C# oracle in `reference/` (golden tests; `reference/Commands/Edit.cs` mirrors `EditOp` in `packages/core/src/edit/ops.ts`; `reference/Commands/MapDump.cs` is the `map` command). New save structures get an oracle command + golden test first.
- Save pipeline: `HorizonSave.save(seed, only?)` hashes+encrypts only emitted pairs; pair paths have no extension (`"main"`, `"Villager0/personal"`); `passthrough` holds non-pair files (landname.dat).
- Worker API (`app/src/worker/handlers.ts`, `protocol.ts`): `build("changed")` = dirty pairs + pairs that loaded with invalid hashes and never resets the changed set; call `api.commit()` only after an in-place write succeeds. `EditSession.absorb()` folds save-time hash bytes into the undo shadow. `api.map()`/`api.itemName()` are read-only; worker results are transferred via `transferables()` (`app/src/worker/transfer.ts`).
- UI edits go only through `edit(op)` in `app/src/lib/state.svelte.ts`; saves are serialized, edits wait for an in-flight save. `applyOp` validates ranges before touching bytes.
- Item `raw` = u64 as 16-digit lowercase hex (`"000000000000fffe"` = none). `"pocket"` = slots 1-20, `"bag"` = 21-40.
- **Map facts** (`packages/core/src/map/`, `app/src/map/`): per-revision offsets are `Revision.mainOffsets` (field item acres 7 wide before 3.0.0, 9 from 3.0.0, height 6). Terrain 112x96 tiles (14-byte tiles) and item layers (32 tiles/acre, 8-byte items) are **column-major** (`index = height*x + y`). World = 9x8 acres at 32 item-tile units/acre (288x256); terrain sits at world (32,32) with 2x2 item tiles per terrain tile; items at x=((9-acreW)/2)*32, y=32; buildings (46 x 0x14 bytes) and plaza are in world item-tile units; buildings drawn as 4x4 item tiles. Ocean/beach colors come from upstream acre templates (`app/public/data/acretiles.bin`, generated by `gen:data`; class 7 = dynamic palette). Item flag regions are treated as opaque raw bytes (upstream sizes/indexes them oddly), so P2 must define flag semantics before editing items. Sprite lookup: `id_count` -> `id_0` -> menu icon -> leaf, with field-item remap (`spriteItemId`). PixiJS 8.23.0 is a lazy chunk (`MapView`); packs live in IndexedDB only.
- Preview under a sub-path needs `BASE_PATH` on `vite preview` too. Don't run `pkill -f` patterns that match your own command line (use `fuser -k PORT/tcp`).

- **Map editor facts** (`packages/core/src/map/`): `mapEdit` op = `{layer, label, changes:[{x,y,raw}]}`; raw id 0xfffe erases the whole footprint covering (x,y), anything else is rooted at (x,y) replacing what it covers (`LayerEditor` in `applyMapEdit.ts`; `planMapEdit` is pure, `applyOp(save, op, {acreTiles})` needs acre templates). Footprints are in item-tile units (a 1x1 item is 2x2 tiles; field items >= 60000 are 2x2); extension tiles hold id 0xfffd, root id, and offsets. Strict rules in `placement.ts`/`ground.ts` (buildable classes: acre classes 0,4,29,44 and dynamic base/road unit models); the example island's own weeds stand on cliff-edge tiles the rules refuse for new placements (allowlisted in `tests/golden/placementConsistency.test.ts`). Flags: policy `untouched` (`flags.ts`; layout unconfirmed, see its comment). Undo is the existing byte-patch `EditSession`; the worker returns `touched` tiles from edit/undo/redo and `mapStore` patches the viewer's copy in place. Planners (`plan.ts`) build ops for tools and bulk actions; `api.mapPlan` plans without editing. Oracle: the `edit` CLI handles `mapEdit` (`reference/Commands/MapEdit.cs`); `item-size` dumps upstream sizes. Svelte `$state` proxies cannot be posted to the worker: use `$state.raw` for anything holding an EditOp.

## P2c terrain brush (done, pushed)
- **Op:** `terrainEdit { label, changes: {x, y, tile}[] }` (`packages/core/src/map/applyTerrainEdit.ts`); x/y are terrain tiles (112x96), tile = the 7 u16 fields, index `96*x+y`, 14-byte records at `landMakingMap`. `planTerrainEdit` is pure and atomic. Rules: tile in a dynamic acre (`staticClassAt` in `ground.ts`), a *changed* ground or road triple must be in the observed table, a changed elevation must lie in the observed range of the ground's `classifyUnit` class, and no tile that was land may become water/cliff/blocked under an item, a building (except types 26/27) or the plaza (pre-existing non-land is ignored). Duplicate coordinates: last wins; equal tiles produce no write and no history entry.
- **Observed table:** `packages/core/src/generated/terrain-observed.json`, built by `bun run gen:terrain [--merge] <saveDir>...` (default `$NHSE_TEST_SAVE`). The example save has **no roads** (only road triple 0,0,0), so no road can be placed until another save is scanned with `--merge`. Rare valid tiles are refused until a save with them is scanned.
- **Oracle:** `reference/Commands/TerrainEdit.cs` (via `edit`; change may carry `rotate: true` for upstream `TryRotate`), byte-identical golden `tests/golden/terrainEdit.test.ts` (ground stamp, elevation, rotate, batch; no road ops).
- **Worker/viewer:** `api.terrainPlan(op)`; edit/undo/redo return `terrain` (`TerrainTouched[]`); the worker reuses one parsed map (`planMap`) for building and terrain plans; `MapStore.patchTerrain` + `terrainVersion`, `MapScene.invalidateTerrain` (re-renders the terrain texture), `onTerrainTouched` in `state.svelte.ts`. UI: `app/src/map/terrainTool.ts` (pure builders: stamp, elevation, rotate, clear road), `TerrainPanel.svelte`, "Terrain" tool (key T) in `MapToolbar`/`MapSection`; `MapView` takes `paintGrid` ("terrain" reports terrain-tile coordinates).
- Tests: 259 unit/golden + 5 e2e pass with `NHSE_TEST_SAVE` (`tests/e2e/terrainEdit.spec.ts` uses canvas screenshots to prove redraw, undo/redo and reload).
- Known gaps: observed-set width and no roads (above); no autotiling (a stamped tile may sit beside mismatched neighbours; in-game acceptance untested); static-acre tiles are not editable; no elevation overlay; stroke ghost shows only the hovered tile; manual look at ghost colours not done.

## Map 3D natural-item models (done, local commits)
- `bun run gen:models --romfs ~/Games/ACNH/romfs [--out personal-models] [--only itemId|itemName]` exports tree, bush, flower, weed, vegetable and stump models from your romfs (build the helper once: `dotnet build scripts/sprites/dotnet -c Release`). The Map page's "Import folder/.zip" accepts the pack (detected by `models.json`); it is kept in IndexedDB (key `models`) and **Clear** removes both packs. 3D draws each model as instanced meshes with lighting and alpha-cut leaves; items without a ready model keep their billboards. Spec/plan: `docs/superpowers/{specs,plans}/2026-11-23-map-3d-models-*`.
- Pipeline (`scripts/models/`): `fgmain.ts` (FgMainParam join: item name -> file, model, colour index; columns `0x87BF00E8` name, `0x39B5A93D` model, `0x48EF0398` file, `0x64B8FFF8` colour, 255 = none), `plantFile.ts` (zstd -> SARC -> BFRES -> `bfres-models` helper command -> models + BNTX), `bake.ts` (grey albedo x colour ramp row, alpha from `_OP`; plain `_Alb` colour albedos are used as is), `generate.ts` (pack writer + `openRomfsModels`), `cli.ts`. Pack format: `app/src/map3d/modelFormat.ts` (manifest v1 + `NMDL` binary geometry; UVs address a horizontal atlas of 128 px cells per textured material, sorted by name). Browser side: `modelPack.ts`, `itemGroups.ts` (`models` groups), `scene3d.ts` (`setModels`).
- Colour rules (summer only): the `*Color00_Grd`/`*PetalColor_Grd` ramp uses the item's colour index (matches the game's table: cosmos white 0, pink 1, red 2, orange 3, yellow 4, black 5); leaf/body/stem ramps use the greenest row; trunk ramps row 0. `MODEL_SCALE = 1/5` (constants.ts). Skipped by design: `Node`/`Anim`/`Snow` models, shadow meshes.
- First full export: 430 items, 196 geometry files, 347 baked textures, 8.4 MB, ~15 s; 110 items skipped (fences, out of scope, plus a few missing models such as `PltVgtPumpkin3`). On the example island: about 440k model triangles, 59 billboards left. Looks right by eye: oaks, cedars, weeds and flowers at the correct scale and orientation (leaf greens are a bit dark).
- Tests: unit (BC4/RGBA8, FgMainParam, bake, pack format, generator on synthetic fixtures, pack import, groupings), romfs-gated golden (`tests/golden/modelsRomfs.test.ts`) and gated e2e (`tests/e2e/map3dModels.spec.ts`: import changes the picture, Clear restores it).
- Known gaps: fixed summer (leaf rows are a heuristic; seasons, snow, sakura/palm shader details unchecked), no wind animation, no fruit on trees, no model picking (clicks pick the ground tile), fences/rocks/shells not covered, performance only judged by triangle count (not measured on a slow GPU).

## Map 3D terrain models (done, local commits)
- With the model pack imported, dynamic terrain tiles that are not plain ground (rivers, cliffs, waterfalls, road overlays) draw as the game's own terrain pieces in 3D; plain ground, static acres, the ocean and beaches stay flat quads. `bun run gen:models` now also exports the pieces (on unless `--only` is given; `--no-terrain` disables). Spec/plan: `docs/superpowers/{specs,plans}/2026-11-23-map-3d-terrain-models-*`.
- Pipeline: `scripts/models/terrain.ts` (unit table `Bcsv/FieldLandMakingUnitModelParam.bcsv`: unit id column `0x54706054` (not the row number), piece name `0x39B5A93D`; piece file = `FldUnit` + name without digits), `terrainBake.ts` (per-material bake from the shared `Model/FldUnit` textures: grass = `mGrass_Grd` ramp pixel at `GRASS` row 56, cliff/river from `_Alb`, waterfall fixed blue, roads `_Alb` or ramp mean), `generate.ts` `exportTerrain`. **Pack format additions:** geometry magic `NMD2` (index groups per material, raw tiling UVs), manifest `terrain` table (`"<unit>_<variation>"` -> model key) and per-model `textures` list (one PNG per material group: `tex/terrain/<material>.png`, 256 px, repeat-wrapped in the browser). Pieces are 10 x 10 model units = one terrain tile; `MODEL_SCALE` 1/5.
- App: `modelPack.ts` (`LoadedModels.terrain`, `textures`), `terrainPieces.ts` (pure: `groupTerrainPieces` -> instances + replaced mask), `buildTerrainMesh(f, replaced)` skips replaced tiles and their walls, `scene3d.ts` draws one multi-material `InstancedMesh` per piece key plus a water sheet per upper-level river tile. `LEVEL_HEIGHT` is now 3 (real cliff depth), `ANGLE_DIR` 1 (river bends connect, verified by eye).
- Measured on the example island: 1268 piece instances (22 keys), about 110k piece triangles + 35k flat; terrain rebuild median 5.2 ms (no incremental patching needed); pack 12 MB total (terrain adds about 3.6 MB: 296 pieces, 17 material textures, export about 20 s).
- Tests: unit (unit table, bake rules, generator on synthetic fixtures, NMD2 format, pack parse, grouping, mesh mask), romfs-gated golden and e2e (`tests/e2e/map3dTerrain.spec.ts`: import changes the picture, a terrain stamp redraws and undoes, Clear restores the flat look).
- Known gaps: roads unverified by eye (the example save has none); grass is a fixed colour (no season, no ground texture/edge blend); river water is a flat translucent sheet (no animation or flow); static acres/ocean/beach unchanged; `Cliff8` piece missing in the romfs table; per-material textures resample cliff/river to 256 px.
